# FOURWARD — 로컬 네트워크 협동 운동회 MVP

최대 5개 조, 조당 2~4명. 사회자 1명은 조 인원에서 제외됩니다.
HTML/JavaScript 화면 + Python 표준 라이브러리 서버이며 외부 패키지 설치가 필요 없습니다.

## 1. 서버 실행

서버 PC에 Python 3.9 이상을 준비하고 이 폴더를 압축 해제합니다.
폴더에서 터미널을 열고 실행합니다.

Windows:
```powershell
py server.py
```

Ubuntu / macOS:
```bash
python3 server.py
```

접속 주소와 사회자 PIN이 터미널에 표시됩니다. 이 터미널은 경기 내내 열어 두세요.
8000 포트가 사용 중이라면 `python3 server.py --port 8080` 또는 `py server.py --port 8080`을 사용합니다.

## 2. 접속

- 사회자 PC: `http://127.0.0.1:8000`
- 참가자: 같은 Wi-Fi/유선 LAN에서 `http://서버PC의LAN_IP:8000`
- 예: 서버 주소가 192.168.0.15라면 `http://192.168.0.15:8000`
- 참가자 기기의 `localhost`나 `127.0.0.1`로는 서버 PC에 접속되지 않습니다.
- `index.html`을 더블클릭하는 방식이 아닙니다. 반드시 서버 주소로 접속합니다.
- 서버가 표시하는 주소가 여러 개면 같은 공유기의 LAN 주소를 선택합니다. Windows `ipconfig`, Linux `hostname -I`로도 확인할 수 있습니다.
- Windows 방화벽 알림이 나오면 신뢰하는 개인 네트워크에 한해 Python 연결을 허용하세요. 방화벽 전체 해제나 인터넷 포트포워딩은 필요 없습니다.
- 게스트 Wi-Fi/학교 AP가 기기 간 통신을 차단하면 접속되지 않을 수 있습니다. 기기 간 통신이 허용된 공유기를 사용하세요.

## 3. 진행 순서

1. 사회자도 이름으로 입장한 후 서버 터미널의 PIN으로 사회자석에 앉습니다.
2. 참가자는 이름으로 입장하고 조의 `＋ 참여`를 누릅니다.
3. 사회자는 조 수를 2~5개로 조절하고 필요하면 랜덤 섞기를 합니다.
4. 랜덤 섞기는 온라인 참가자 모두(사회자 제외)를 배정합니다. 별도의 관전자를 제외할 필요가 있으면 수동 편성을 사용하세요.
5. 참여 조마다 2~4명이 되면 경기 시작. 빈 조는 경기에 포함되지 않습니다.
6. 매 스테이지는 조 번호 순서대로 한 조씩 진행합니다. 각 조는 4초 준비 후 최대 3분간 플레이하며, 완주하거나 시간이 끝나면 다음 조가 자동으로 준비를 시작합니다. 모든 조의 차례가 끝나면 스테이지 결과가 표시됩니다.
7. 사회자가 다음 스테이지를 시작합니다. 마지막은 누적 점수로 공동 우승까지 표시합니다.
8. `대기실로`는 점수와 경기 기록을 초기화합니다. 참가자 이름과 조 편성은 유지됩니다.

## 4. 경기 규칙

### 임시 AI로 혼자 테스트하기

사회자로 입장한 뒤 각 조의 `＋ 임시 AI` 버튼으로 자동 참가자를 한 명씩 추가합니다.
2개 이상의 조에 각각 2~4명을 구성하면 혼자서도 경기 시작이 가능합니다.
AI는 네 경기 모두 자동으로 입력하며 사람과 같은 인원 보정·점수·입력 제한을 적용받습니다.
사람과 AI를 같은 조에 배치할 수도 있습니다. 미로에서는 사람이 맡은 방향은 직접 입력해야 합니다.
AI는 테스트용으로 정확한 박자를 사용하므로 실전 경쟁용 난이도는 아닙니다.

대기실에서 `AI 1명 제거` 또는 `임시 AI 전체 제거`로 삭제합니다.
랜덤 섞기에 AI도 포함되며, 조 수를 줄여 대기 인원으로 이동한 AI는 전체 제거로 삭제할 수 있습니다.
`대기실로`로 돌아오면 AI 편성도 유지됩니다. 서버를 종료하면 AI는 사라집니다.

| 스테이지 | 입력 / 목표 | 보정 |
|---|---|---|
| 협동 미로 | 담당 방향키로 팀 캐릭터를 녹색 출구까지 이동 | 4명 U/D/L/R, 3명 UD/L/R, 2명 UD/LR |
| 리듬 계주 | 카운트다운 후 표시된 방향을 0.65초 박자에 입력, 8구간 통과 | 총 8구간 동일, 참가 횟수 차이 최대 1회 |
| 줄넘기 | 줄이 발밑에 올 때 Space, 성공 진행도 15 | 성공 인원 ÷ 팀 인원을 매 회차 누적 |
| 박 터뜨리기 | 바 중앙에서 Space, 중앙30/안쪽20/가장자리10 피해 | 체력 = 팀 인원 × 150 |

- 계주: 현재 주자만 입력. 한 패턴은 5개 방향이며 ±0.22초 허용. 놓치거나 틀리면 같은 주자가 같은 패턴을 다시 시도합니다. 다음 주자는 해당 카운트다운 때 공개됩니다.
- 줄넘기: ±0.18초 허용. 회차당 1회만 시도 가능하며 이른 입력도 시도를 소비합니다. 5박마다 80→100→70→110 BPM 순환, 변속 2박 전부터 예고합니다. `박자 소리 켜기`로 보조음을 켤 수 있습니다.
- 박: 바 주기 2.2초. 주기당 1회 공격, MISS도 시도를 소비합니다. 팀원별 바 시작 위치가 다릅니다.
- 모바일은 화면 버튼, PC는 방향키/Space. 키를 누른 채로 유지하는 자동 반복은 무시됩니다.
- 화면 왼쪽에는 조별 대기·진행·완료 상태와 누적 점수, 오른쪽에는 현재 경기 중인 한 조의 중계가 나옵니다. 대기 중이거나 차례가 끝난 조의 입력은 차단됩니다.

화면은 크림색 배경과 단풍색·황토색·올리브색의 가을 운동회 테마를 사용합니다.
3스테이지에서는 현재 BPM에 맞춰 줄이 회전하고, 실제 Space 입력을 받은 참가자의 캐릭터가 점프합니다.
성공 입력은 캐릭터 강조로 표시되며 일시정지하면 줄과 점프 동작도 멈춥니다.

## 5. 순위

조별 플레이 시작부터 완주까지 걸린 시간이 짧은 순서로 100/80/60/40/20점입니다. 대기시간과 준비시간은 기록에 포함되지 않습니다. 완주 시간이 0.1초 단위로 같으면 공동 순위입니다.
미완주는 완주 조 뒤에 진행률로 배치하고 동일 진행률은 공동 순위입니다.
미로 진행률은 현재 위치에서 출구까지 남은 최단 거리로 계산합니다.
줄넘기·계주·박은 각각 성공 진행도·통과 구간·피해 비율을 사용합니다.
총점 동점은 공동 우승입니다. 공동 순위 다음 순위는 건너뜁니다(1,1,3...).

## 6. 연결·제한사항

- 상태는 서버가 공유하며 약 0.18초 간격으로 가져옵니다. 움직이는 바와 박자는 클라이언트에서 부드럽게 그립니다.
- 판정은 서버가 입력을 받은 시각 기준입니다. 표시 시계는 왕복 지연으로 근사 보정하지만 입력 지연 자체는 보상하지 않습니다. 서로 다른 기기·Wi-Fi 지연으로 판정 오차가 생길 수 있는 레크리에이션용 MVP입니다.
- 실전 전에 동일 환경에서 짧게 연습하세요. 공식 경쟁용 정밀 지연 보정과 안티치트는 미포함입니다.
- 한 브라우저 프로필은 참가자 한 명입니다. 여러 명을 PC 하나로 테스트하려면 별도 브라우저 프로필/브라우저를 사용하세요. 일반 탭은 토큰을 공유합니다.
- 새로고침 시 같은 브라우저에서 기존 참가자로 복귀합니다. 시크릿 창을 닫거나 사이트 데이터를 지우면 복귀 정보가 사라집니다.
- 접속 끊김은 이름 옆에 표시됩니다. 자동으로 인원 보정을 다시 적용하지 않습니다. 사회자가 일시정지 후 재접속을 기다려 주세요.
- 서버 재시작 시 경기·명단·점수는 초기화됩니다. 영구 저장, 기권 참가자 삭제, 개별 스테이지 연습, 관전자 전용 비밀권한은 미포함입니다.
- HTTP 신뢰 LAN용입니다. 인터넷에 직접 공개하지 마세요. 사회자 PIN은 서버 터미널에서만 확인할 수 있습니다.
- 리듬 계주 향후 주자 순서는 클라이언트에 공개하지 않습니다. PIN과 다른 사람의 참가자 토큰도 응답에 포함하지 않습니다.
- 미로는 인원이 적으면 소통 부담이 줄어듭니다. 인원 보정은 완전한 경쟁 균형을 보장하지 않으므로 가능하면 동일 인원 편성을 권장합니다.

## 7. 검증

```bash
python3 -m unittest -v test_game.py
```

게임 로직상 20명/5개 조의 네 스테이지 완주, 2·3·4명 보정, 권한 제한, 타임아웃, 중복 입력 제한, 조별 순차 진행과 대기 조 입력 차단, 임시 AI의 전체 경기 완주, 줄넘기 점프 이벤트, HTTP 20개 참가 세션을 검증합니다. 실제 20대 기기의 무선 지연과 브라우저별 음성·터치 동작은 현장 확인이 필요합니다.
